核心运行规则

  1. 只拆分批准范围内具有独立交付价值的任务；按契约和依赖判断可并行性。
  2. 同时预留槽位与写入/测试资源；满槽停止新增，已有任务继续执行。
  3. 逐项处理结果，确认实际资源释放后滚动补位，不等待整批完成。
  4. 使用不可变基线、独立工作区和明确写入归属；严格模式另需实际权限边界。
  5. 保留自测、技术验证、组合验证和配置要求的独立审核；证据绑定精确产物版本。
  6. 用户取消、外部阻塞或范围完成时停止/暂停；不通过 Hook 无限续跑。

严格执行模式缺少必要能力时阻塞对应路径，不自动降级。审核者由部署配置与授权指定，具体产品或模型不是用户原始需求中的硬性限制。

1. 文档目的与约束等级

本文件规定插件需要解决的问题、必须提供的行为、不能夸大的能力，以及实施后的验收方法。它可以作为开发蓝图、任务拆分、接口设计和版本验收的依据。

本文区分三种内容，避免把建议、当前实现情况或宿主限制误写成用户已经确认的需求：

标记 含义 处理方式
UR 当前对话中用户明确提出的要求 产品目标和验收应保持这些要求；变更需有明确的用户指令依据。
FR / NFR 为落实用户目标而细化的功能或非功能要求 作为本需求基线的实施要求；实现方法可以调整，但不能降低对应用户目标。
D / V 设计决策、建议默认值，或尚待验证的能力 不得表述为用户原话或已完成事实；改变时记录原因、影响和验证结果。

当前可见用户指令没有指定正式审核者必须是某个产品、某个人或 ChatGPT，也没有指定固定模型、永久固定的并发数、跨机器部署方式或绝对实时延迟。独立审核是可配置的质量机制，具体审核方和授权路径须由项目配置或后续明确指令确定。

3. 产品目标与衡量方式

3.1 主要目标

在保持质量要求、授权范围和资源边界的前提下，缩短从明确需求到可验收交付的总耗时。

插件应能够把已经批准的开发工作拆成具有明确接口和交付物的任务，维护任务之间的依赖关系，持续派发满足条件的工作，并在任何一项任务释放资源后及时补位。

3.2 不以“跑满槽位”替代目标

以下行为不属于有效并行：

  • 为占满槽位而重复实现同一功能。
  • 在接口尚未确定时让多个任务各自猜测公共行为。
  • 把很小的依赖步骤过度拆分，造成更高的沟通和集成成本。
  • 通过减少必要测试、降低既定模型质量或省略审核来制造更快的表面结果。
  • 为维持运行数量而扩展用户没有要求的功能。

没有合格任务时允许空槽。需要等待外部输入或审核时允许暂停，并提供具体阻塞原因。

3.3 建议度量

必须记录整体交付耗时、就绪任务等待时间、确认释放到下一次派发的延迟、技术验收首次通过率、返工率、集成冲突数量和资源使用情况。模型调用消耗可在宿主提供数据时记录。

并发利用率是辅助指标。不能仅凭一次跑满槽位，宣称插件已经提高开发效率。

4. 术语与状态边界

术语 定义
任务 Task 已批准范围内具有目标、输入、修改边界和验收条件的工作单元。
执行尝试 Attempt 某任务的一次实际执行；重试必须使用新的尝试身份和代次。
就绪 Ready 任务当前满足依赖、输入、冲突、权限和资源准入条件。
并发槽 Slot 按明确口径计量的容量；可能对应进程、打开的原生线程或其他受控执行实例。
候选产物 Candidate 执行者提交的代码或其他结果，尚不等同于已验证或正式验收。
资源租约 Lease 某次执行对写入范围或其他独占资源的有效占用记录。
栅栏标识 Fencing Token 用来拒绝旧执行尝试继续发布或释放新资源的单调代次或等效机制。
技术验证 对准确版本的编译、测试、接口、行为和集成检查。
正式验收 由配置的授权流程对准确交付版本作出的最终接受决定。
宿主适配器 Adapter 将统一任务与事件协议映射到 Codex 或 ZCode 实际支持接口的模块。

必须区分：结果提交、模型回合停止、代理线程关闭、执行进程终止、资源释放、技术验证通过和正式验收通过。任何一种状态都不能在缺少证据时自动替代其他状态。

5. 功能要求

以下功能是对 UR-01 至 UR-09 的工程细化。其实现状态见第 10 节，不能把“必须实现”读成“当前已经实现”。

5.1 项目与能力配置

FR-01：显式项目范围。 插件只能在明确选择并授权的项目范围内工作。应记录项目、工作树、请求和任务身份，避免把不同项目或不同请求的状态混在一起。

FR-02：宿主能力诊断。 在依赖某项能力前，报告宿主名称、版本、执行位置、有效配置、可用工具、Hook 信任状态、身份与生命周期可观察范围，以及实际隔离能力。能力记录必须区分“文档描述”“源码核对”“本机检测”“真实测试通过”。

FR-03：配置可追踪。 并发预算、资源预算、重试预算、审核策略、运行模式和策略版本应有明确配置来源。插件不得自行提升宿主权限、使用未经配置的高权限模式或伪造已获授权。

5.2 任务建模与机会发现

FR-04：任务契约。 每个派发任务至少记录任务编号、批准计划版本、目标、基线提交或输入快照、接口版本、依赖门槛、可修改范围、资源需求、验收标准和预期交付证据。

FR-05：依赖图。 检测缺失依赖和环路，明确任务进入就绪状态的条件。依赖解除必须基于指定版本的产物或契约，不能只根据自然语言“已经完成”判断。

FR-06：语义独立性。 并行准入不能只检查文件是否不同，还应考虑公共接口、数据结构、单位、错误行为、事务约定、配置、依赖和生成资源的相互影响。

FR-07：持续评估。 初始拆分完成后，在执行结束、取消确认、依赖解除、资源释放、计划调整和验证反馈等关键事件后重新评估可并行工作。评估应覆盖当前批准范围，不能为了填槽制造额外需求。

FR-08：合理粒度。 拆分应形成可以独立交付和验证的结果，并考虑上下文准备、交接和集成成本。插件应能够保留必要串行步骤，不能把“所有任务都并行”作为成功条件。

5.3 原子准入与滚动调度

FR-09：统一预算账本。 对插件承诺管理的执行范围，维护一个权威容量账本。计数必须包含适用的预留、启动中、运行中、停止中及状态不明实例，不能把“正在等待”自行解释为不占宿主槽位。

FR-10：原子申请。 任务资格、容量和独占资源必须在同一原子准入流程中确认并预留。多个并发申请不能同时消费同一个最后空槽，也不能产生同一任务的重复活跃实例。

FR-11：满槽排队。 达到适用预算上限后，停止新增执行实例，继续接收事件并维护队列。已有工作不因“满槽”被无故停止。

FR-12：确认后滚动补位。 任意实例的结束或关闭得到确认后，释放可以释放的占用，刷新就绪任务并继续派发。有合格任务时不应等待同批其他任务全部完成。

FR-13：适用的全局范围。 插件必须说明预算的边界，例如单请求、单宿主会话、单机器控制器或跨项目服务。不能把宿主的会话内线程限制称为跨进程、跨项目或跨机器的全局上限。

FR-14：公平与质量工作容量。 验证、集成、关键依赖修复和等待较久的任务应有获得容量的机制，避免新开发工作长期占满资源，造成验证积压和下游阻塞。

5.4 生命周期、恢复和取消

FR-15：任务与执行分离。 独立记录交付阶段和执行实例阶段。任务提交候选结果后可以释放已真正结束的执行资源，但不能因此自动改变技术验证或正式验收状态。

FR-16：可证明的释放。 依据宿主实际计数口径确认线程或实例结束；独占写入资源还必须确认旧写入者停止，或者其写入和发布权限已被有效撤销。

FR-17：重复与迟到事件。 事件处理、资源释放和结果发布应幂等。旧尝试的结果、审核或释放通知不能覆盖新尝试，也不能释放新租约。

FR-18：恢复而非盲目重启。 启动明确失败时回退预留；启动结果不明、事件丢失或控制器重启时，先核对实际运行状态再重试。心跳超时本身不能证明实例已经停止。

FR-19：有界重试。 重试次数、时间和资源预算必须明确。只对已诊断的瞬时失败或范围内可修复问题重试。不能自动反复执行副作用不明或不可逆的操作。

FR-20：取消优先。 用户取消后停止新增准入，并按配置终止或收尾现有实例。Hook 不得撤销取消意图。全部完成、无可运行任务且只能等待外部条件、或恢复预算耗尽时，应结束或暂停并解释原因。

5.5 独立工作区与冲突控制

FR-21：写入范围与输入固定。 每个写任务必须绑定准确基线、工作区和修改范围。共享公共接口、根构建配置、依赖锁文件、数据库迁移和集成引用应有明确负责人或串行更新机制。

FR-22：运行资源隔离。 对构建输出、端口、测试数据库、生成文件、后台进程和其他可变资源分别分配命名空间或独占租约。独立 worktree 不能被当作完整的操作系统权限隔离。

FR-23：实际执行边界。 承诺严格隔离的模式必须覆盖实际写入和发布路径。若仍可从其他编辑工具、Shell、未受控后代或共享系统权限绕过，就不得宣称严格隔离，并应阻塞依赖该保证的执行路径。使用协作模式必须符合已有授权或经明确选择，不能自动降级继续执行。

FR-24：禁止静默降级。 请求选择严格受控模式而能力不足时，应阻塞该执行路径并报告缺口。改用协作模式属于显式策略变更，不能在后台自动发生。

5.6 开发质量、证据与审核

FR-25：质量门槛保持。 并行开发必须遵守既有编译、测试、接口、回归及其他验收要求。不得为提高并发率而删除失败检查、放宽标准或把跳过的验证写成通过。

FR-26：精确版本证据。 交接至少包含任务与尝试身份、计划版本、基线和候选版本、实际修改路径、接口版本、实际验证命令、环境、结果及已知限制。结果要区分通过、失败、跳过和不确定。

FR-27：集成验证。 同一集成引用通过受控的单一写入入口更新。候选修改应在当前集成基线组成的实际代码版本上验证；旧分支或旧组合的报告不能证明新组合正确。

FR-28：可配置独立审核。 支持配置独立于实现者的技术检查和正式审核流程。启用该流程时，审核者身份、权限与所批准的准确版本必须可追踪；执行者不能凭自报字段自行通过正式审核。审核方可以是用户配置的人、服务或代理，不固定为 ChatGPT。

FR-29：证据保留与清理。 执行槽回收可以先于工作区删除。清理前保留候选结果、必要日志和交接材料，并确认资源空闲。不能强制删除用户未提交修改或把破坏性仓库操作当作冲突解决办法。

5.7 英文指令、Skill 和 Hook

FR-30：英文注入。 插件自产的模型指令、AGENTS 受管理块、Skill 工作流程、角色提示、Hook 附加上下文、拒绝与续跑原因应使用英文。用户原始需求可以作为标识清楚的数据保留原语言；用户回复语言不被强制改为英语。

FR-31：按宿主发现规则注入。 解析实际生效的指令文件及作用域。不能假定口头的 agent.md 与宿主支持的 AGENTS.md 等价，也不能靠新建高优先级 override 抢占用户规则。

FR-32：幂等文件管理。 文件注入应使用唯一受管理块，记录版本、摘要和归属，保留块外内容、BOM 与换行形式。同版本重复注入不产生重复块；块内用户修改应拒绝覆盖并给出冲突说明；卸载只删除插件拥有且仍匹配的内容。

FR-33：工作流程可复用。 Skill 应覆盖准入条件、拆分、派工、结果交接、依赖门槛、验证、失败处理和停止条件，并调用宿主实际提供的工具。Skill 文本不得被描述为会自动创建工具、权限或常驻服务。

FR-34：两端独立 Hook 适配。 使用各宿主真实的事件名称、配置包装、字段、超时单位和返回格式；不虚构子代理事件或参数。需要阻止操作的检查应放在实际执行前的可用同步入口。

FR-35：如实报告 Hook 生效情况。 安装、启用、信任和实际执行是不同状态。应验证并报告 Hook 的覆盖缺口、错误、超时和输出解析行为，不能假定所有异常都会阻止工具执行。

FR-36：Hook 与控制器职责分开。 Hook 负责触发检查或传递事件；控制器负责持久事实、原子准入和调度；受控执行器负责实际权限边界。不能用一句“请执行 Skill”代替应由程序执行的确定性约束。

5.8 安装、升级、诊断与交付

FR-37：可审查的安装。 安装流程应先列出将生效的文件、配置和宿主差异，再执行已授权的变化。不得覆盖无关配置，不代替用户或宿主完成需要真实信任的授权步骤。

FR-38：安全升级和卸载。 活跃任务期间升级应按明确策略暂停新增并排空或取消；失败可诊断。卸载保留用户修改与必要任务证据，不强制清理活动工作区。

FR-39：文档与状态真实。 每个发行版本应包含需求、开发蓝图、兼容性、配置、安装/卸载、协议、验收和实际验证记录。必须区分设计模板、参考组件、已实现运行时和已通过真实宿主验收的能力。

FR-40：完成发行包。 可安装成品必须包含清单引用的真实程序和资源，并通过其声明目标的安装与运行验证。引用不存在运行时的 .example 模板不能冒充完整插件发行版。

6. 非功能要求

NFR-01：可靠性与可恢复性

关键状态和事件应持久化，恢复时可识别重复、乱序、未知启动与未终止实例。持久状态损坏或关键事实不确定时，优先保护现有结果和独占资源，不以重新派发掩盖不确定状态。

NFR-02：质量与性能同时评估

性能比较应使用相同任务、相同既定模型/推理配置和相同验收门槛，记录总交付时间和质量结果。不能承诺未实测的固定加速倍数或“绝对零缺陷”。

“立即补位”指确认事件到达后及时进入下一轮调度，不引入无必要的整批等待。控制器调度开销、宿主进程启动耗时和模型响应耗时应分别记录。设计提出的本机无争用 500 ms 调度目标属于待实测的建议指标，不是用户已指定的硬实时上限。

NFR-03：权限边界真实

不得突破宿主权限、用户授权、平台配额或 Hook 信任机制。若全部代理仍以同一系统身份拥有任意写入权限，不能声称控制器数据库、正式审核记录和其他工作区具有不可绕过的保护。

NFR-04：兼容性可追踪

适配声明必须绑定明确的宿主版本或源码提交、执行位置和测试环境。不同产品、版本和部署形态分别验证，不能把本地 Codex 的结果延伸为 Work Cloud 已支持，也不能把某次 Linux 测试写成 Windows 验收通过。

NFR-05：配置和使用可理解

错误信息应说明任务、资源、依赖或能力缺口，而不是只要求用户重复重试。正常流程应复用现有授权，不为每次可逆的内部调度另设无必要的人工确认。只有实际超出授权、需要外部决策或发生不可自动解决的冲突时才暂停。

NFR-06：可维护与可观察

协议、策略和适配器应有版本。日志应能关联项目、请求、任务、尝试、资源和准确产物，但不应无必要记录密钥或凭据。度量应足以判断是否发生超额、资源泄漏、重复派发、验证饥饿或补位延迟。

NFR-07：依赖和部署范围明确

共享核心应尽量减少不必要依赖，复用用户已有模型和宿主能力。具体实现语言、数据库和平台打包方式属于设计决策。当前用户没有为本插件提出特定模型供应商或新增的免费服务约束，不能从其他项目自动继承这类限制。

  • CreateWorkflow 不提供逐 Agent 的 worktree 隔离；旧 Workflow 描述中的隔离选项不能冒充已实现能力。

Parallel Development 插件系统设计

设计版本 1.0.0 · 2026-11-03

1. 产品目标与边界

在已经批准的开发范围内，不降低质量门槛，持续寻找可独立交付、独立验证的工作。存在就绪任务和可用资源时滚动派发；达到上限时仅停止新增；任一执行实例安全结束后立即重新调度，不等待整批任务结束。

效率指标是整体合格交付时间。槽位利用率是辅助指标。不得通过重复开发、制造额外需求、降低模型能力、跳过测试或提前放行依赖来填满槽位。

绝对零缺陷、自动识别全部语义冲突、发现所有最优拆分不属于可证明承诺。可以验证的承诺是：受控入口不超额、共享写入资源不被同时授予、未知状态不被当作退出、证据绑定具体版本、未审核产物不被标为正式通过。

本次交付为设计和参考资源。正式运行时及两个真实宿主的端到端测试仍需按实施计划完成。

2. 两种能力模式

2.1 cooperative_native：原生协作模式

使用 Codex/ZCode 自带子代理或工作流，插件提供英文规则、Skill、可观察操作的同步 Hook、任务登记、交接和集成检查。

可承诺范围限于适配器实际观察并控制的任务。原生子代理共享权限、缺失身份字段、缺少关闭回执、未继承 Hook、内部工作流调用不经过同一入口等，都会限制强制程度。禁止用提示词或函数名推断工作区已经隔离。

该模式适合阅读、调查、测试设计，以及经过责任划分的协作开发；工作区与权限未隔离时，不把它称为严格隔离模式。doctor 必须显示能力缺口，不能静默降级。

2.2 controlled_executor：受控执行模式

共享控制器拥有唯一派发入口，按任务启动独立宿主 Worker 进程，将每个 Worker 放入独立工作树和可验证沙箱。控制器维护全局账本，负责槽位、资源、进程树、退出确认、取消和滚动补位。Worker 禁止再创建未经登记的代理。

严格隔离要求真实 OS/容器权限边界，以及 Worker 无法改写的控制器状态和审核入口。仅设置 cwd、环境变量、只读提示词、同用户可写 JSON 文件不能提供这些保证。

Linux 可采用已验证的独立 namespace/容器沙箱及进程组管理；Windows 需采用实际可用的隔离权限机制，并用 Job Object 等管理整个进程树。Job Object 本身不是文件权限隔离。若所需能力不可用，严格模式拒绝启动并给出英文原因；用户可明确选择协作模式。

控制器只管理自己的授权任务，不启动额外进程绕过宿主、账户、模型或平台限制。

4. 角色与宿主拓扑

逻辑职责设为：主 Agent 对外；请求调度者澄清与组织；组长协调；Worker 执行命令。正式独立审核由项目配置和授权指定的审核方完成；不限定为某个产品或模型。本地验证和交叉检查不能伪装为最终批准。

逻辑角色不必等于一个长期存活的模型线程。协调状态可以持久化，等待事件时不反复推理。

Codex 按实际打开的子线程计数，不能把管理角色随意排除。ZCode 原生普通子代理不能递归创建后代；适配器把组长/执行者映射为主调度者管理的扁平角色任务，或者由受控运行时管理逻辑层级。不得要求原生 Worker 调用不存在或被禁止的孙代理工具。

5. 并行准入规则

任务仅在以下条件全部满足时进入 READY：

  1. 属于当前批准计划和范围，计划版本未失效。
  2. 目标、交付物、验收方式明确。
  3. 依赖达到指定门槛；接口契约已确定且版本一致。
  4. 固定代码基线和输入产物，不读取其他工作者正在变化的工作区。
  5. 写入范围和独占资源与当前租约不冲突。
  6. 执行环境可以满足需要的隔离与资源条件。
  7. 拆分收益合理，没有重复实现同一目标。

依赖允许 contract_ready、implementation_verified、integrated_verified、final_accepted 四种门槛。接口已冻结时，可在批准的测试替身上并行实现；真实集成必须验证实际实现组合。

文件不重叠不证明语义独立。契约需包含字段、单位、错误语义、兼容性、事务边界和版本。共享头文件、根构建文件、依赖锁、迁移序号等分配一个修改负责人。

读不可变快照可共享；不要为全部读取加独占锁。路径声明只支持首版的规范化精确路径和目录前缀，禁止无法可靠求交的任意 glob。重命名同时占用源和目标；删除属于写入；解析 symlink、Windows 大小写、卷/UNC 和仓库外路径。

6. 两条状态机

交付状态

PLANNED → READY → IMPLEMENTING → SUBMITTED → TECHNICALLY_VERIFIED → AWAITING_REVIEW → ACCEPTED

旁路状态：BLOCKED、REWORK、CANCELLED。TECHNICALLY_VERIFIED 仅代表约定的技术检查通过，不代表正式独立审核通过。

执行实例状态

RESERVED → STARTING → RUNNING → STOPPING → EXIT_CONFIRMED → RELEASED

旁路状态：START_FAILED、LOST、CANCELLED_CONFIRMED。

每次执行有独立 attempt_id 和递增 generation。任务被重试、恢复、重新派发时，不复用旧实例授权。迟到事件只能作用于对应实例。

提交结果、模型回合停止、线程关闭、进程树退出和产物验收是不同事实。禁止用自然语言“完成”直接驱动 RELEASED 或 ACCEPTED。

7. 资源预算

分别维护：插件管理的 Worker 进程数、宿主原生线程数、模型请求配额、构建 CPU/内存和测试资源。不能把几个不同口径都命名为同一个 max_agents。

共享控制器跨批准项目和请求使用一个全局 Worker 预算，并按项目/请求设置子预算。宿主原生上限始终有效。若多个控制器进程共存，必须使用同一实际资源服务或唯一领导者；各自一份 SQLite 文件不构成全局限制。

计数包含 RESERVED、STARTING、RUNNING、STOPPING 及尚未确认退出的 LOST。空闲的原生线程如仍计入宿主上限，也必须计数。

验证/集成同样需要资源。队列积压时动态提高验证、关键依赖和集成优先级。可以保留可借用的验证容量，但禁止把全部容量永久用于新开发。

构建并行度应和 Worker 数量联动，防止每个 Worker 都使用全部 CPU。

8. 原子预留协议

在同一数据库事务中：

  1. 验证 task、plan revision、scope digest 与授权主体。
  2. 校验依赖门槛和对应产物版本。
  3. 确认该任务没有活跃实例。
  4. 校验全部预算和路径/资源租约。
  5. 创建 attempt，预留容量及资源，写入有唯一幂等键的启动 outbox。
  6. 提交后由执行器启动。

SQLite 首版可使用 BEGIN IMMEDIATE、唯一约束和受控写入路径；不使用“先读计数，再另行加一”。账本位于控制器管理目录，不应放进 Worker 可写工作树。

启动明确失败时释放预留。启动结果不明时进入 reconciliation，不直接再次启动。事务不能包含外部进程启动，outbox 和执行器幂等键用于处理崩溃窗口。

令牌和租约是插件内部协议，不得擅自加入 Codex/ZCode 原生工具 schema。适配器以支持的调用 ID、外部账本和真实实例 ID 建立关联。

9. 滚动补位与机会发现

以下事件触发调度：计划注册/修订、接口就绪、实际实例退出、资源解除、验证结束、返工、取消、宿主容量变化。

每次先应用并去重事件、核对资源，再刷新 READY 队列，持续派发至预算用尽或无合格任务。任一短任务结束后，下一任务应在仍运行的长任务结束前开始。

优先级综合关键路径、可解锁任务数、验证积压、等待时间和资源匹配；增加 aging 避免低优先级任务永久饥饿。

“持续寻找”采用事件和关键里程碑触发的规划，而非不断全仓扫描。已有 READY 队列由程序调度；尚未发现的新节点由 Planner 按 Skill 识别。自动拆分仅能细化批准范围，不能扩展功能或修改验收标准。

调度器的“立即”定义为事件接收后的尽快调度，并记录 event_received_at、slot_released_at、next_start_requested_at。模型和宿主启动延迟单独统计。建议把本机无争用调度开销目标设为 500 ms 内；这是待测目标，不是已达成性能。

全部完成、用户取消、预算停止或仅剩外部阻塞时结束/暂停。没有活动任务却全为 BLOCKED 时报告阻塞链，不能空转。

10. 完成、取消与故障恢复

实例退出确认以宿主关闭回执，或受控执行器确认进程及相关写入子进程结束为准。结果先持久化，再释放可释放的执行资源；工作区保留至验收或明确放弃。

租约过期/心跳丢失只能证明失联，不能证明旧执行者已停止。重新授予冲突资源前，应终止旧实例，或通过真实执行边界撤销旧 generation 的写入/集成权。仅在数据库修改一个标记不能阻止遗留 Shell 继续写磁盘。

取消顺序：禁止新增 → 请求停止 → 等待有界宽限期 → 终止进程树/隔离 → 确认 → 释放。保留已有产物和必要证据。进程识别应包含启动时间等信息，避免 PID 重用造成误杀。

控制器恢复后逐项核对 RESERVED/STARTING/RUNNING/LOST 与宿主实际状态。重复事件无副作用；旧 attempt 不能归还新 attempt 的槽位；恢复或 SendMessage 重新执行也要走准入。

失败重试需要有界次数和退避；相同原因反复失败应进入 BLOCKED，不能无限重试消耗模型额度。

11. 英文 AGENTS 注入

规范目标为宿主实际读取的 AGENTS.md。用户口头的 agent.md 不自动等价于小写单数文件。Codex 同目录 AGENTS.override.md 会优先生效，嵌套目录也可能提供更近的规则。

默认项目级 opt-in。全局安装只注册能力，不应给所有项目注入并行策略。仅在选中的项目执行文件写入或 Hook 激活。

注入两层：

  • managed-file：安装时写入稳定英文核心规则，采用 begin/end 标记、版本和内容摘要，保留块外字节。
  • context：SessionStart/恢复/压缩后的适用事件注入精简英文规则及状态摘要；派工时带上 Worker 任务卡。不能假设每种宿主都具有所有生命周期事件。

不应每个事件重写 AGENTS.md。动态任务状态保存在控制器，经 Hook 或任务简报传入。

更新与卸载必须：保留 BOM 和换行风格；同版本重复操作不改文件；出现多个标记、缺失标记、用户改动受管块或路径逃逸时停止写入并提供差异；卸载只移除精确受管块，不能以旧备份覆盖整个用户文件。

不要自动新建 override 文件来抢优先级。若已有 override，显示实际生效文件，使用明确选择的目标或者仅采用上下文策略。对嵌套范围和独立 worktree，doctor/执行器必须重新解析实际生效路径。

同一项目同时使用两个宿主时，不能假定只有一个有效目标。Codex可能读取已有AGENTS.override.md，ZCode仍读取最近AGENTS.md。完整安装器应按宿主分别解析、去重实际目标，建立逐目标所有权manifest；必要时选择经授权的两个英文块或只使用对应宿主上下文注入。不得为了统一路径自动创建/删除override。本包参考注入器仅管理一个明确目标，不承担这套多宿主来源解析。

所有插件自产模型文本使用英文。用户消息作为任务数据保留原语言；用户可继续收到中文答复。注入不得要求模型忽略更高优先级指令、权限或用户停止要求。

12. Skill 设计

提供一个主 Skill parallel-development，详细流程见 spec/parallel-development.SKILL.md。触发范围是多步骤开发、模块实现、重构、排障、验证与集成；不需要用户每次明确说“并行”。

Skill 包含：能力检查、批准范围确认、DAG和契约、任务卡、写入范围、派发、完成核对、技术检查、集成、正式审核与清理。方法说明和反例可以放 references；高频核心规则留在英文 AGENTS 块中。

不得把“已加载 Skill”写成“已执行全部规则”。可程序化要求由控制器检查。不要同时把同一 Skill 安装到插件目录和项目发现目录造成重复来源。

13. Hook 适配与短路径

所有 Hook 为薄适配层：读取 stdin JSON → 校验字段与来源 → 归一化事件 → 调用共享控制器 → 转为宿主支持的输出。可阻断的准入检查使用同步路径；日志和汇总可异步。

Codex 的 command/timeout 秒/commandWindows 与 ZCode 的 process/command+args/timeoutMs 毫秒分别生成，不共用一个原始 hooks.json。

SessionStart：仅对 opt-in 项目提供英文策略与必要状态，不触发全面开发。

PreToolUse：针对已验证覆盖的创建、恢复、编辑、命令和集成入口进行检查；未知写入路径必须交给受控执行器，不能靠不完整字符串匹配宣称完全隔离。

PostToolUse/Failure：记录真实结果、启动失败或调用信息；后置拒绝不能撤销已发生的写入。

Stop/SubagentStop：只处理宿主支持的语义。可请求有限继续，但不以“仍有任意未完成任务”为无限续跑条件。外部审核/用户输入阻塞或用户取消必须允许停止。

Codex SubagentStop 不证明关闭。ZCode 不制造不存在的 SubagentStart/SubagentStop 事件。宿主后台完成通知、运行时 RPC 或受控进程退出是独立证据来源。

Hook 输入大小、超时和响应字段设上限；只解析需要的字段，默认不保存完整用户 prompt/密钥/工具输出。ZCode camelCase/snake_case 别名同时存在且值不一致时应拒绝歧义，不能随意取一个。

14. Hook 失败与强制边界

插件配置存在、被发现、已信任、实际执行、成功阻断是不同状态。doctor 分别报告。

当前宿主 Hook 可能跳过未信任声明，部分失败可能不阻断操作，部分工具不走同一路径。生产严格模式不能把 Hook 自身当作唯一边界。执行和集成入口必须再次检查许可；控制器不可用、许可过期、身份不明时不得进入受控写入。

ZCode 某些源码能力如 onError:deny 需探测后才使用；模板不把未验证的扩展字段当通用保证。固定源码中的 parseHookStdout 对空输出、非对象文本或 JSON 解析失败会返回无结果；进程退出码为0时，这些情况不触发 onError:deny。成功解析后违反输出schema才属于另一类错误。严格准入仍需受控执行入口独立检查。不要自动写 trust store、默认关闭权限检查或采用 yolo 来让测试通过。

15. 宿主能力清单与 doctor

输出至少包括：engine/version/source hash、execution location、manifest loaded、skill discovered、active instruction path、hook registration/trust/invocation、spawn/resume/close observation、worker identity、cwd isolation、write coverage、native concurrency semantics、wake-up behavior、sandbox/process-tree control。

每项区分 documented、source_verified、detected、integration_tested、unsupported、unknown。模板通过 JSON 解析不等于实际宿主加载通过。

Codex 本地和 Work Cloud 分开。ZCode 固定源码与用户已安装版本可能不同；版本匹配也不能代替能力测试。

doctor 不通过时，完整打印英文机器结果及可理解中文解释，不静默转为弱模式。允许用户明确选择 cooperative_native。

16. 受控 Worker 驱动

进程调用使用参数数组，不使用字符串拼接 Shell。明确继承用户已有模型/账号配置，不复制凭据到任务文件，不擅自切换便宜模型降低质量。

Codex 驱动需按目标版本核实非交互执行、工作目录、JSON事件和关闭/进程结束语义。禁用 Worker 内二次委派使用已验证宿主配置；未验证字段不得写入原生参数。

固定 ZCode 源码支持以下形状（实际参数经 doctor 再核对）：

zcode --cwd <worktree> --prompt <task text> --output-format stream-json
      --workflow-mode disabled
      --disallowed-tools Agent,Task,Workflow,CreateWorkflow,AmendWorkflow,ResumeWorkflowRun,SendMessage
      --mode guarded

这里是 argv 形状说明，不是要求把多行原样复制为 Shell 命令。当前非交互默认模式存在 yolo 行为，适配器必须显式设置受控权限模式；其余无法交互处理的 ask 应返回阻塞或拒绝，不自动批准。用户原始授权仍然是任务执行的前提。

模型结果/stream-json最终result与OS进程树退出分别记录。Windows长prompt命令行长度及进程列表可见性需要限制并探测；不能虚构 ZCode 的 --prompt-file 参数。可采用受控本地任务文件简报引用，但须测得读取/执行语义，不承诺无损透明。

17. 文件与资源隔离

每个执行任务：独立 worktree + branch + build/output/temp；固定 base_commit；分配端口/测试数据库/schema/测试账号命名空间；只读依赖可共享。

工作树初始化只在干净、明确基线操作。保留用户未提交变更，不对共享仓库执行破坏性清理。自动清理仅限工具自己创建且仍归其所有的工作树；存在未保存改动时暂停清理。

路径授权包含规范化后的真实路径及类型。构建输出不写入其他 Worker 目录。集成分支更新只有一个授权入口；并行验证使用各自不可变候选快照。

18. 质量门槛与正式审核

G0：计划、任务、接口、范围清楚。G1：Worker实现与相关自测。G2：范围检查、契约检查和风险相称的独立技术检查。G3：当前集成基线上的真实组合验证。G4：约定的正式独立审核。G5：授权后交付/发布和清理。

修改代码、接口或依赖后，受影响的旧证据失效。证据记录 commit/tree hash、命令 argv、环境摘要、退出码、结果和日志摘要。旧日志不能冒充本次运行。

Worker只能提交候选和证据，不能设置最终 ACCEPTED。正式审核记录需绑定计划版本、产物摘要、审核者身份和时间。强制不可伪造必须由Worker不可访问的审核通道及状态存储保证；同用户可写文件只提供协作记录。

小而低风险的变更采用相关检查，不强制每次全量昂贵验证。公共接口、并发、持久化和授权边界的改变需要相应更强的组合验证。

19. 共享服务接口

spec/controller-api.en.md

Shared controller protocol — design version 1

This is the proposed interface of the plugin's runtime. These operation names are not existing Codex or ZCode tools. A future CLI or MCP server may expose them only after implementing authentication, persistence, host adapters, and execution boundaries. No scheduler service is included in this design package.

Transport and authority

Use one controller per real resource domain. A local Unix-domain socket or Windows named pipe should have an explicit operating-system access policy. A TCP transport, if later added, requires authenticated encrypted connections and explicit origin/tenant handling. A random task ID or a producer field is not authentication.

The controller owns its database, launch outbox, cancellation endpoint, and final-review records outside worker-writable worktrees. Workers receive only the capability needed for their assigned attempt. A same-user unrestricted process can often access other same-user resources; a strict deployment must establish a real sandbox, distinct principal, or equivalent brokered boundary. Do not describe ordinary filesystem permissions under one unrestricted user as sufficient isolation.

Use distinct principals for planning, execution observation, technical verification, integration, and formal review. The execution gateway, not a worker report, attests that a process tree has stopped. The review authority, not an executor or verifier, records final acceptance. Approval covers an exact plan revision and scope digest; a field named approved supplied by a worker is not evidence of approval.

Request envelope

Every mutating request carries protocol_version, request_id, idempotency_key, project_id, an expected state revision where applicable, and an operation-specific body. Resolve the authenticated principal from the transport. Do not trust a body-provided identity. A duplicate idempotency key with the same canonical body returns the recorded result; a different body with that key returns IDEMPOTENCY_CONFLICT.

Bound request size, string length, event rate, and replay retention. Store the request body digest and result in the same transaction as the state change. Use a controller-generated monotonic event sequence for ordering; remote wall-clock timestamps are descriptive, not an ordering authority.

A no-capacity result is normal backpressure, not a reason to create an unmanaged worker.

Admission transaction

The following is normative pseudocode, not a supplied executable:

begin immediate transaction
  verify caller, enabled project, approved scope, and plan revision
  verify task graph, fixed baseline, and dependency evidence
  reject any active attempt for the task
  determine every applicable host, process, and resource budget
  check normalized path/resource conflicts against active leases
  reserve budgets and leases
  create a new attempt ID and increment its generation
  create one launch-outbox item with a stable idempotency key
  append the state event and recorded request result
commit

The executor consumes the outbox after commit. It must reconcile an existing launch with the same identity before creating another process. A database transaction cannot atomically include an operating-system launch. A lost launch acknowledgement is an uncertain instance, not a proven failure.

Count RESERVED, STARTING, RUNNING, STOPPING, and unresolved LOST instances against the applicable budget. An open native thread may remain counted even after a model turn stops. Do not release a host-thread reservation until its native closing fact is confirmed. Use separate counters for active workflow asks and provider requests; neither substitutes for the managed-worker budget.

Event acceptance

schemas/event.schema.json defines the envelope. Its payload is deliberately event-specific; the receiving handler must additionally validate its versioned payload contract and authenticated producer.

Event family Additional required facts
Run reserved/start acknowledged Task, attempt, generation, allocated resources, actual native handle or executor launch identity.
Run reported Candidate digest and evidence references; explicitly not a terminal occupancy fact.
Run exit/cancel confirmed Authorized observer, actual handle identity, exit/termination facts, remaining descendant status, and time observed.
Run lost Last observation and uncertainty reason; no automatic release.
Technical verification Exact candidate and contract digests, check identities, environment digest, outcomes, and verifier identity.
Integration verified Exact previous integration baseline, candidate set, resulting tree/commit, and checks on that combination.
Review recorded Exact plan and integrated delivery digests, decision, designated reviewer, and authenticated review record.

Check the transition against the current attempt generation and controller revision. Record stale observations for diagnosis without changing a newer attempt. A repeated terminal event must never return another slot. A new resume is a new admission even when the host reuses the native agent ID.

Rolling dispatcher

Persist the task graph and reverse dependency index. On each accepted material event, recompute only affected eligibility, then choose a compatible set of READY tasks using critical-path priority, validation backlog, age, and resource fit. Acquire the actual reservations transactionally; a previously computed selection is only a proposal.

Start admitted tasks until a relevant budget is full or no eligible compatible task remains. Do not await the longest sibling before processing another result. Trigger planning at meaningful scope/contract milestones to discover additional work inside the approved plan. Do not trigger unlimited model planning after every tool event.

If a host's verified native workflow already owns the rolling queue, do not run a second independent scheduler over the same slots. Assign one owner of each capacity domain, correlate its events, and state which global protections remain unavailable in cooperative mode.

Evidence and integration

Evidence must identify source baseline, produced tree/commit, contract versions, exact command argv, working directory, environment summary, result, exit status, timestamps, and bounded log/artifact references. skipped and not_run are distinct from passed. A source, contract, dependency, or environment change invalidates the relevant evidence according to declared applicability.

An integration candidate contains the expected integration-ref value. Update that ref only through the integrator after verifying the actual candidate combination. If the baseline changed, recompute and reverify affected checks before a compare-and-swap update. A clean merge proves only that a textual operation succeeded.

The local development agent's self-tests and an internal verifier can establish technical readiness. They do not replace the independent review authority specified by the user's workflow. Wait for that authority when required; do not use Stop continuation to fabricate approval.

Recovery and shutdown

Persist reservations, outbox entries, observed handles, process identity including start-time information, and generation ownership. On restart, reconcile every nonterminal instance before launching replacements. A heartbeat expiry does not terminate a process. Before reassigning an exclusive resource, confirm termination or enforce a real revocation boundary that rejects old-generation access.

On cancellation, prevent new admission first; request shutdown; wait a bounded grace period; terminate the owned process tree where authorized; confirm; then release. Retain evidence and unmerged candidates. Never kill a process solely by a stale PID. An uncertain stop remains visible and consumes the relevant safety reservation.

The default design allows two automatic retries after the first attempt. All retries remain within task, elapsed-time, cost, and permission budgets. Do not retry unknown irreversible side effects. If no runnable work remains, report the blocker and stop/pause without busy polling.

}

Return this only when the controller confirms executable authorized work, the user has not cancelled, and the per-run continuation budget remains. Do not return it merely because tasks are awaiting external input or formal review. The proposed plugin limit is two; ZCode also has its own bounded Stop continuation behavior. A Stop hook is not an indefinite daemon or a general idle-conversation wake-up mechanism.

Input normalization

Codex uses hook_event_name, session_id, tool_name, tool_use_id, and tool_input on the corresponding events. When both aliases are present and disagree, report an ambiguous input and refuse the affected controlled operation.

For asynchronous ZCode Agent calls, a launch result is not a completion event. For Codex, SubagentStop is not proof that its thread has closed. A controller-generated normalized run_exit_confirmed event requires separately verified terminal facts.

An untrusted, skipped, malformed, timed-out, or unsupported hook does not prove a denial occurred. Record each failure distinctly. This option also does not cover every skip/cancel path. The controlled execution gateway must independently fail admission when the controller or required capability is unavailable.

    "additionalContext": "Use the parallel-development Skill for the authorized task. Dispatch only dependency-ready work under the configured resource budget. Preserve the user's permission boundaries."
  }
}

A concrete denial for a managed operation:

{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "This managed operation has no valid execution lease. Reconcile the task state before retrying."
  }
}

An event with no additional action returns {}. ZCode does not treat arbitrary plain stdout as injected context. If updatedInput is ever used, it must be a complete replacement accepted by the tool's schema; do not add invented task_id, cwd, or worktree fields to native Agent input. Carry task metadata in supported prompt fields and the trusted state store.

For Stop, { "decision": "block", "reason": "..." } requests another turn. The pinned runtime limits consecutive Stop continuations to three. The adapter must respect stop_hook_active, cancellation, an empty eligible queue, resource saturation, unresolved dependencies, and circuit-breaker state. Stop is an advisory continuation boundary, not the scheduler's event loop. A full pool should wait for a real completion event; it should not repeatedly force model turns.

Failure behavior and trust

The template sets onError: "deny" only on synchronous PreToolUse. At the pinned commit, an executed handler that fails or times out is translated into a denial for that tool call. A JSON object that parses successfully but fails the host's output schema also raises a hook error. Exit code 2 is a supported blocking path. Other hook events do not acquire this guarantee by setting the same property.

There is a material parsing exception: parseHookStdout() silently returns no result for empty stdout, text that does not start with {, or a JSON parse failure. With exit code 0 these cases do not trigger onError: "deny". Thus the host hook protocol is not universally fail closed for malformed output. The future adapter must validate and serialize its complete response before writing it, exit with a blocking failure when it cannot produce a valid response, and test this distinction explicitly. Strict execution must still be admitted by the external supervisor or another verified execution boundary; it cannot rely solely on ZCode converting arbitrary stdout corruption into a denial.

The future installer must probe the installed host's actual execution-error, timeout, parsed-schema-error, and malformed-stdout behavior with inert diagnostic calls before describing its admission guarantees. An older host may not support onError, or may ignore an unknown field. Do not silently remove this setting and continue to advertise the same enforcement. If a required check fails, report the capability gap and disable managed admission or offer an explicitly labeled advisory mode. Do not compensate by weakening permissions or enabling yolo.

onError: "deny" applies to a hook that was actually executed. It does not make an unloaded plugin, an untrusted skipped project hook, user cancellation, or a child runtime without hooks into a protected boundary. The independent supervisor must refuse new strict-mode worker admissions while its required control-plane health checks fail. A hook error does not authorize releasing an occupied slot; reconcile the actual worker and process tree first.

Plugin hooks follow plugin loading and enablement. A user runtime hook switch is not proof that every plugin hook is disabled. Confirm the actual loaded declarations and diagnostics in a new session.

Current project hooks have a separate trust flow. When a user chooses to put hooks in project runtime configuration, the documented sequence is review, inspect the concrete commands and source, then grant the exact reviewed digest:

zcode hooks trust review --workspace /absolute/project --json
zcode hooks trust grant --workspace /absolute/project --hook-digest REVIEWED_SHA256
zcode hooks trust status --workspace /absolute/project --json

These lines describe the host's trust interface; this design does not run them or grant trust. Opening a project, setting hooks.enabled, or changing permission mode does not grant project hook trust. Changed declarations require a new review. A skipped SessionStart is not replayed in the current session. Do not bypass this trust mechanism or treat a corrupt trust store as authorization.

Optional runtime configuration fragment

runtime-hooks.json.example is a narrow fragment for a user who has already chosen to enable runtime-configured hooks. It is not a replacement configuration file and is not required merely to demonstrate this plugin template.

A future installer must read and parse the existing configuration, preserve every unrelated top-level field and every existing hooks field, and change only the requested hooks.enabled value. Keep existing events, limits, and declarations intact. Show the resulting change before any required approval, and support restoration. Do not register the plugin's standard hook file again in hooks.events.

If existing configuration cannot be parsed, stop that edit and report the parse error. Do not replace it with this fragment. Enabling hooks does not grant project hook trust and does not alter tool permissions.

Child-agent and scheduling compatibility

At the pinned commit, ordinary Agent child runtimes are constructed without the parent's hook configuration or hook runner. Parent tool-event mirroring does not close this gap. The ordinary child also inherits the parent working directory, has no native cwd or worktree argument, and cannot spawn further subagents. English AGENTS instructions or a Skill remain behavioral guidance in that path.

Consequently, native collaboration mode may use task contracts, bounded dispatch, completion notifications, independent reviews, and worktree conventions, but must not claim that these hooks enforce every child write. SendMessage can resume a terminal child in the background; admission accounting must handle resumes as well as new Agent calls. A copied <task-notification> string is not an authenticated completion record.

The newer CreateWorkflow engine provides a real queue, max_concurrency, and immediate refill when an active ask settles. Its actor contexts can remain alive while idle, so its cap is not a count of all surviving contexts. Its process-wide governor limits provider/model requests and is not a cross-process worker semaphore. It offers no per-actor worktree isolation option. Workflow children inherit runtime configuration differently from ordinary Agent children, but this must be capability-tested; do not generalize that behavior to ordinary Agent or to every direct workflow command surface.

The older Workflow tool is a separate API. Its description mentions worktree isolation and nested workflows, but the pinned implementation throws for both. Do not use those descriptive claims as release capabilities.

Strict mode requires the future external supervisor, independent worker processes, verified sandbox boundaries, centralized resource leases, authoritative lifecycle events, and serialized integration. A Git worktree separates normal file paths; it does not prevent out-of-tree writes. An independent ZCode CLI worker can use the verified --cwd, --prompt, --output-format stream-json, --workflow-mode disabled, and --disallowed-tools flags, but these flags alone are not a sandbox. Headless -p defaults to yolo in this source, so select an intentional permission mode and preserve existing restrictions. Do not change to yolo to make denied work succeed.

Validation required before release

The implementation must validate the native plugin manifest and source discovery, one hook invocation per intended registration, JSON protocol output, explicit denials, missing executables, timeouts, corrupt responses, output-size limits, platform paths, and preservation of existing permissions and configuration. Test ordinary Agent and CreateWorkflow child coverage separately, and report their actual guarantees.

Exercise background launch versus completion, resumed agents, cancellation, worker crash recovery, duplicate events, lease reconciliation, and saturation without busy loops. Strict-mode acceptance also requires sandbox escape-boundary tests, process-tree termination confirmation, and conflict-free serialized integration. Until these checks pass on the installed host version, label this adapter a design template rather than an accepted runtime.

This directory contains a runnable, standard-library Python reference component. It is not the proposed scheduler, a plugin installer, a host-capability doctor, or a security sandbox.

Commands

That override behavior is conservative and host-neutral. ZCode's reviewed default loader does not use Codex's override precedence. A production multi-host installer must resolve each host's effective sources and use per-target ownership records or verified context injection. This reference component supports one active target per explicit project; it does not perform that full multi-host installation.

Behavior

The component preserves existing bytes outside its managed markers, UTF-8 BOM, the selected newline convention, and the target's mode. It records a content digest, original-byte backup, and managed-block identity under the project's .parallel-dev directory. Repeated application of the same block is idempotent. An update replaces only a matching owned block. Removal preserves user edits outside that block and never restores the entire old backup over the current file.

Edited, duplicated, missing, or unowned markers require manual resolution. Symlinks, special files, ambiguous case variants, invalid backups, and another active mutation lock are rejected. A pending operation journal prevents a new mutation until its exact before/after state has been inspected. Metadata and backups are retained after removal.

The component intentionally refuses to guess recovery for an interrupted multi-file operation. It does not scan for repositories, modify global settings, grant Hook trust, spawn agents, or inspect the full instruction chain. It does not guarantee protection against a malicious process with the same operating-system authority racing filesystem operations. The complete runtime requires stronger platform-specific boundaries.

Required semantic validation

Schema validation is necessary but cannot replace these runtime checks:

  1. Authenticate the caller and resolve its authorized project, plan, and role.
  2. Validate the plan revision and approved scope digest through the designated authority.
  3. Reject cycles, missing dependency producers, self-dependencies, and incompatible gate/contract references.
  4. Resolve project-relative paths against the actual workspace and normalize symlinks, case, separators, volumes, and directory ancestry before computing conflicts.
  5. Bind baselines and evidence to real immutable artifacts; reject stale, missing, or mismatched digests.
  6. Allocate budgets, task ownership, and exclusive resources atomically.
  7. Validate event-specific payloads, authenticated producer permissions, generations, and legal state transitions.
  8. Preserve separate facts for model completion, thread closure, process-tree exit, technical verification, and formal acceptance.
  9. Derive the effective execution profile from required capabilities. A client-supplied integration_tested label is not sufficient proof.
  10. Check the argv, working directory, environment, permissions, and resource cost of each requested validation command before execution.

Critical event payload contracts

The event envelope rejects unknown top-level properties. The following payloads and their nested records also reject unknown properties; extending them requires an explicit protocol change. An enclosing attempt_id always requires both task_id and generation, and an enclosing generation always requires both identity fields.

Event Required binding and payload
resource_released Enclosing task, attempt, and generation; exact lease_id, resource_id, resource_kind, release_basis, and nonempty immutable evidence_refs.
evidence_submitted, technical_verification_passed Enclosing task, attempt, and generation; plan containing id, revision, and scope_digest; exact artifact_digest; nonempty evidence_refs.
integration_verified Exact plan, integration_ref, integration_baseline, integration_result, nonempty candidates, and nonempty evidence_refs. Each revision binds a Git commit and artifact digest; each candidate binds task, attempt, generation, and artifact digest.
review_recorded Exact plan, delivery_digest, decision, review_record_id, and review_authority identity. Decisions are approve, reject, or rework; optional evidence_refs, when supplied, must be nonempty.
run_exit_confirmed Enclosing task, attempt, and generation; process_tree_terminated, an exit_fact with stable instance identity and observation time, and nonempty evidence_refs.

Integration and review may describe a project or a task without an enclosing attempt. Candidate attempts remain explicit inside an integration payload. The controller must resolve them to the approved plan and reject duplicate or incompatible candidate ownership; array uniqueness alone does not enforce that rule.

Every evidence reference contains an evidence-store id and its content digest. The referenced record must exist, be immutable, originate from an authorized observer where required, and cover the exact event target. A technical-pass reference must contain the required check identities, contract bindings, environment, and outcomes. Schema validity cannot turn submitted evidence into a technical pass or establish the authenticity of a final review. In particular, producer and review_authority fields are claims for correlation; authenticate the actual caller and validate the review record through the designated independent authority.

For a process-tree exit, exit_fact.kind is process_tree_exit, an actual exit code or terminating signal is required, and process_tree_terminated must be true. For a confirmed native thread closure, the kind is native_thread_closed and process_tree_terminated must be null: the host closure supplies no process-tree termination fact. A stopped model turn is neither kind. Remaining descendants or an unknown exit must remain nonterminal and must not be represented by a false terminal claim.

Release evidence must be appropriate for the exact resource. A lease expiry is not a release basis. effective_write_revocation is structurally restricted to an exclusive_write_scope; it cannot free a still-running process or an open native-thread slot. The controller must also verify every other basis against the actual execution profile and reservation, reject old-generation releases, and apply an idempotent state transition atomically. A valid event can still be stale, unauthorized, or false.

The remaining event types retain open payload objects in this design schema. Their receiving handlers must implement separate versioned contracts before those events may cause a state change. Handler semantics and transport authorization are described in ../spec/controller-api.en.md; the document is a design contract, not implemented validation code. Parsing JSON or checking these structures does not verify host compatibility, authenticated facts, or concurrency invariants. Use a Draft 2020-12 validator with explicit format validation during implementation; the format keyword alone does not guarantee date-time validation in every validator configuration.

Retry policy

The task schema permits zero, one, or two automatic retries after the initial attempt, consistent with the global limit of two. The effective limit is the stricter of the task and project policy; elapsed-time, cost, permission, and side-effect constraints still apply. Retry eligibility and generation changes are runtime decisions, not consequences of schema validity.

Protocol changes require explicit schema and adapter versioning. Do not let individual adapters silently fork task or lifecycle semantics.

## Select the operating profile

Choose and record one profile for the request:

- `cooperative_native`: use the host's native agent tools, verified notifications, supported Hooks, and a shared task ledger. Identify separable outcomes within the approved scope. Prefer tasks with stable inputs, a clear owner, and a meaningful independently verifiable result. Avoid splitting tiny dependent edits merely to increase agent count.

1. Reconcile observed host/executor state with the ledger.
2. Record new evidence without treating a completion message as final acceptance.
3. Refresh affected dependencies and conflict compatibility.
4. Select ready work that fits current capacity and resources.
5. Admit and start compatible work until capacity or eligible work is exhausted.

Process results individually. Do not wait for an entire batch merely because it started together. When the native workflow already provides a verified rolling queue, integrate its events with the controller instead of creating a conflicting second scheduler.

Prioritize tasks that unlock critical dependencies, fix verified blockers, or reduce validation/integration backlog. Include queue age to prevent starvation. Provide each writer with a unique workspace and a stable baseline. Assign separate build outputs and mutable test resources. Give shared interfaces, root build configuration, dependency lock files, migrations, and integration references explicit owners.

Require each handover to include:

- Task and attempt identifiers, source baseline, contract versions, and delivered commit or artifact digest.
- Actual changed paths and any requested scope deviations.
- Implemented behavior, incomplete work, and known limitations.
- Commands/checks actually performed, relevant environment, outcomes, and evidence locations.
- Dependencies or integration decisions requiring attention.

Distinguish `passed`, `failed`, and `skipped`. Never reuse an old test report as proof for a changed artifact. Choose verification appropriate to the change and retain all required existing quality gates. Do not weaken tests to make a candidate pass.

Let the integrator update a shared integration reference through one controlled entry. Verify the current integration baseline combined with the candidate. Parallel verification is acceptable on immutable, identified snapshots. Return ambiguous semantic conflicts to the appropriate owner rather than guessing a new public contract.

Record technical readiness separately from formal review. Prepare the exact combined delivery and evidence for the designated independent reviewer. A worker, verifier, or integrator cannot approve its own work as the final review authority.

Keep result submission, model-turn stopping, native-thread closure, process termination, and formal acceptance separate. Use the host/executor's actual terminal-state evidence to release capacity. Before reassigning an exclusive mutable resource, confirm that the old writer has stopped or has lost effective permission to write or publish.

Use attempt generations and fencing identifiers. Make release operations idempotent. Ignore stale completions for a newer attempt. A missed heartbeat is uncertainty, not permission to run a conflicting replacement. Preserve candidates and evidence through verification and authorized cleanup.

Unless the approved configuration is stricter, permit two automatic retries after the initial attempt, for three attempts total. Apply the request's elapsed-time and resource budgets as additional limits. Retry only when the failure is diagnosed as transient or a bounded repair remains within scope. Reconcile unknown side effects before retrying; do not repeat an irreversible action blindly.

If all remaining work requires external input, review, unavailable resources, or a changed requirement, report the specific blocker and pause. Do not make a Stop Hook continue indefinitely because the task table is nonempty.

Report completed deliverables, unresolved blockers, actual validation results, formal-review status, and known capability gaps. State whether the run used cooperative native orchestration or a verified controlled executor. Distinguish fixture checks from real-host tests. Never claim zero defects, complete isolation, automatic background persistence, or support for an untested host profile.

### Purpose

### Responsibilities

- Check actual changed paths against ownership and scope.

- Add focused verification fixtures only within the verifier's expressly allocated scope.
- Distinguish passed, failed, skipped, and inconclusive checks, including relevant commands, environment, and evidence.
- Tie each finding to the exact artifact and explain its effect and required correction.
- Report technical readiness or specific rework needs without making a formal acceptance decision.

### Boundaries

## Integrator

### Purpose

Combine technically eligible candidates into an identified integration revision and verify their joint behavior through a single controlled update path.

### Responsibilities

- Confirm each candidate's baseline, contracts, ownership, dependency gate, and technical evidence.
- Own the update lease for the integration reference, or use the controlled integration service that owns it.
- Apply eligible changes to an integration workspace without overwriting user work.
- Validate the actual combined revision; invalidate stale evidence when the relevant code or contract changes.
- Return unresolved semantic conflicts to the responsible coordinator and module owners.
- Preserve the combined commit/artifact digest and its validation evidence for formal independent review.
- Clean up only confirmed idle, plugin-owned temporary resources after required evidence and candidates are retained.

### Boundaries

Do not let multiple integrators write the same integration reference concurrently. Do not use destructive repository resets, force pushes, or unapproved default-branch merges to simplify integration. Do not reinterpret a public contract without coordination. Do not reuse tests from a different combined revision as proof. Do not convert technical integration success into final acceptance.

## Independent Review Authority

The configured independent review authority remains outside the automatic worker/verifier/integrator acceptance loop. Formal approval must target the exact delivered revision and approved plan revision. Self-reported flags, a successful Hook, or a local technical pass cannot substitute for this decision.

If the implementation claims workers cannot forge formal approval, enforce that claim through a protected service or permission boundary. When all agents retain unrestricted writes under the same operating-system identity, describe the arrangement as a cooperation policy rather than an unforgeable security guarantee.

## Shared Recovery and Handover Rules

Use distinct task and attempt identities. Separate candidate submission from model-turn completion, native-thread closure, process termination, resource release, and final acceptance. Reconcile uncertain instances before replacement. Use generation-aware, idempotent release and publication operations.

Unless the approved configuration sets a lower limit, allow two automatic retries after the first attempt. Apply request-level time and resource budgets too. Stop when failures repeat without a new diagnosis, when authority is missing, or when external input is required. Respect user cancellation and do not create unbounded Stop continuation loops.

class InjectionError(Exception):
    """A validation/update error that must not be treated as successful installation."""


def digest(data: bytes) -> str:
    return hashlib.sha256(data).hexdigest()


def encoded(data: bytes) -> str:
    return base64.b64encode(data).decode("ascii")


def decoded(value: object) -> bytes:
    if not isinstance(value, str):
        raise InjectionError("Invalid byte encoding in the injection manifest.")
    try:
        return base64.b64decode(value, validate=True)
    except (ValueError, TypeError) as exc:
        raise InjectionError("Invalid byte encoding in the injection manifest.") from exc


def check_directory(path: Path) -> None:
    """Check each existing component without resolving away a symlink."""
    for component in (path, *path.parents):
        try:
            mode = component.lstat().st_mode
        except FileNotFoundError as exc:
            raise InjectionError(f"Directory does not exist: {component}") from exc
        if stat.S_ISLNK(mode):
            raise InjectionError(f"Symbolic-link directories are not supported: {component}")
        if not stat.S_ISDIR(mode):
            raise InjectionError(f"Expected a regular directory: {component}")


def read_file(path: Path) -> tuple[bytes | None, int | None]:
    """Read a bounded regular file; reject symlinks and special files first."""
    try:
        info = path.lstat()
    except FileNotFoundError:
        return None, None
    if stat.S_ISLNK(info.st_mode) or not stat.S_ISREG(info.st_mode):
        raise InjectionError(f"Expected a regular file, not a symlink or special file: {path}")
    if info.st_size > MAX_BYTES:
        raise InjectionError(f"File exceeds the {MAX_BYTES}-byte reference-tool limit: {path}")
    flags = os.O_RDONLY | getattr(os, "O_NOFOLLOW", 0) | getattr(os, "O_BINARY", 0)
    try:
        descriptor = os.open(path, flags)
    except OSError as exc:
        raise InjectionError(f"Cannot safely open file: {path}: {exc}") from exc
    with os.fdopen(descriptor, "rb") as stream:
        opened = os.fstat(stream.fileno())
        if not stat.S_ISREG(opened.st_mode):
            raise InjectionError(f"File changed to a non-regular object: {path}")
        data = stream.read(MAX_BYTES + 1)
    if len(data) > MAX_BYTES:
        raise InjectionError(f"File grew beyond the reference-tool limit: {path}")
    return data, stat.S_IMODE(opened.st_mode)


def case_guard(directory: Path, canonical_names: tuple[str, ...]) -> None:
    """Avoid creating competing guidance names on case-insensitive systems."""
    if not directory.exists():
        return
    check_directory(directory)
    names = [entry.name for entry in directory.iterdir()]
    for canonical in canonical_names:
        matches = [name for name in names if name.casefold() == canonical.casefold()]
        if len(matches) > 1 or (matches and matches[0] != canonical):
            raise InjectionError(
                f"Case-variant or duplicate name for {canonical}: {', '.join(matches)}. "
                "Resolve the naming conflict explicitly before using this tool."
            )


def block_span(data: bytes) -> tuple[int, int] | None:
    begin_count, end_count = data.count(BEGIN_TOKEN), data.count(END_TOKEN)
    if begin_count == end_count == 0:
        return None
    if begin_count != 1 or end_count != 1:
        raise InjectionError("Missing, duplicate, or malformed managed policy markers.")
    start, closing = data.index(BEGIN_TOKEN), data.index(END_TOKEN)
    if closing <= start:
        raise InjectionError("Managed policy markers are out of order.")
    for position in (start, closing):
        if position != 0 and data[position - 1:position] != b"\n":
            if not (position == len(BOM) and data.startswith(BOM)):
                raise InjectionError("Managed policy markers must start on their own lines.")
    first_newline = data.find(b"\n", start)
    if first_newline < 0:
        raise InjectionError("The managed begin marker is incomplete.")
    first_line = data[start:first_newline + 1]
    if not re.fullmatch(
        rb'<!-- parallel-development:managed-policy:begin version="[A-Za-z0-9._+-]+" -->\r?\n',
        first_line,
    ):
        raise InjectionError("The managed begin marker has an unsupported format.")
    end_newline = data.find(b"\n", closing)
    end = len(data) if end_newline < 0 else end_newline + 1
    last_line = data[closing:end]
    if last_line not in (END_MARKER, END_MARKER + b"\n", END_MARKER + b"\r\n"):
        raise InjectionError("The managed end marker must occupy its complete line.")
    return start, end


def load_policy(path: Path) -> bytes:
    check_directory(path.parent.absolute())
    raw, _ = read_file(path)
    if raw is None:
        raise InjectionError(f"English policy source is missing: {path}")
    if len(raw) > MAX_POLICY_BYTES:
        raise InjectionError("The policy source exceeds the 128 KiB reference-tool limit.")
    if raw.startswith(BOM):
        raw = raw[len(BOM):]
    try:
        text = raw.decode("utf-8")
    except UnicodeDecodeError as exc:
        raise InjectionError("The policy source must be UTF-8 text.") from exc
    if re.search(r"[\u3400-\u9fff]", text):
        raise InjectionError("The injected policy source must not contain CJK instructions.")
    normalized = text.replace("\r\n", "\n")
    if "\r" in normalized:
        raise InjectionError("The policy source contains unsupported bare carriage returns.")
    result = normalized.encode("utf-8")
    if not result.endswith(b"\n"):
        result += b"\n"
    if block_span(result) != (0, len(result)):
        raise InjectionError("The policy source must contain exactly one complete managed block.")
    return result


def newline_for(data: bytes) -> bytes:
    first = data.find(b"\n")
    return b"\r\n" if first > 0 and data[first - 1:first] == b"\r" else b"\n"


def json_bytes(value: dict) -> bytes:
    return (json.dumps(value, indent=2, sort_keys=True, ensure_ascii=True) + "\n").encode("utf-8")


def atomic_write(path: Path, value: bytes, expected: bytes | None, mode: int = 0o600) -> None:
    check_directory(path.parent)
    observed, _ = read_file(path)
    if observed != expected:
        raise InjectionError(f"File changed since inspection; refusing to overwrite it: {path}")
    descriptor, temporary_name = tempfile.mkstemp(prefix=f".{path.name}.", dir=path.parent)
    temporary = Path(temporary_name)
    try:
        with os.fdopen(descriptor, "wb") as stream:
            stream.write(value)
            stream.flush()
            if hasattr(os, "fchmod"):
                os.fchmod(stream.fileno(), mode)
            os.fsync(stream.fileno())
        check_directory(path.parent)
        observed, _ = read_file(path)
        if observed != expected:
            raise InjectionError(f"File changed while preparing an update: {path}")
        os.replace(temporary, path)
    finally:
        if temporary.exists():
            temporary.unlink()


def guarded_delete(path: Path, expected: bytes) -> None:
    check_directory(path.parent)
    observed, _ = read_file(path)
    if observed != expected:
        raise InjectionError(f"File changed; refusing to delete it: {path}")
    path.unlink()


class Injector:
    def __init__(self, project: str | Path, target: str | None = None, policy_path: Path | None = None):
        supplied = Path(project)
        if not supplied.is_absolute() or ".." in supplied.parts:
            raise InjectionError("--project must be an explicit absolute path without '..' components.")
        if supplied == Path(supplied.anchor):
            raise InjectionError("The filesystem root cannot be used as a project.")
        check_directory(supplied)
        if target is not None and target not in TARGETS:
            raise InjectionError("--target must be AGENTS.md or the existing AGENTS.override.md.")
        self.project = supplied
        self.target_name = target or "AGENTS.md"
        self.target = supplied / self.target_name
        self.metadata = supplied / ".parallel-dev"
        self.backups = self.metadata / "backups"
        self.manifest_path = self.metadata / STATE_NAME
        self.pending_path = self.metadata / PENDING_NAME
        self.lock_path = self.metadata / LOCK_NAME
        self.policy = load_policy((policy_path or DEFAULT_POLICY).absolute())

    def validate_paths(self) -> None:
        check_directory(self.project)
        case_guard(self.project, TARGETS + (".parallel-dev",))
        for name in TARGETS:
            read_file(self.project / name)
        if self.metadata.exists() or self.metadata.is_symlink():
            check_directory(self.metadata)
            case_guard(self.metadata, (STATE_NAME, PENDING_NAME, LOCK_NAME, "backups"))
            for name in (STATE_NAME, PENDING_NAME, LOCK_NAME):
                read_file(self.metadata / name)
            if self.backups.exists() or self.backups.is_symlink():
                check_directory(self.backups)

    def load_manifest(self) -> tuple[dict | None, bytes | None, bytes | None]:
        raw, _ = read_file(self.manifest_path)
        if raw is None:
            return None, None, None
        try:
            record = json.loads(raw.decode("utf-8"))
        except (UnicodeDecodeError, ValueError) as exc:
            raise InjectionError("The injection manifest is invalid; preserve it for inspection.") from exc
        if not isinstance(record, dict) or record.get("schema_version") != 1 or record.get("component") != COMPONENT:
            raise InjectionError("Unrecognized injection manifest schema or owner.")
        if record.get("project") != str(self.project) or record.get("target") not in TARGETS:
            raise InjectionError("The injection manifest belongs to a different project or target.")
        if record.get("state") not in ("active", "removed") or type(record.get("original_existed")) is not bool:
            raise InjectionError("Invalid installation state in the injection manifest.")
        backup_name = record.get("backup_file")
        if not isinstance(backup_name, str) or not re.fullmatch(r"[a-f0-9]{64}-[a-f0-9]{12}\.bin", backup_name):
            raise InjectionError("Invalid backup reference in the injection manifest.")
        check_directory(self.backups)
        original, _ = read_file(self.backups / backup_name)
        if original is None or digest(original) != record.get("original_sha256"):
            raise InjectionError("The original-byte backup is missing or has changed.")
        managed = decoded(record.get("managed_base64"))
        if digest(managed) != record.get("managed_sha256") or block_span(managed) != (0, len(managed)):
            raise InjectionError("The recorded managed block is invalid.")
        if decoded(record.get("separator_base64")) not in (b"", b"\n", b"\r\n"):
            raise InjectionError("The recorded insertion separator is invalid.")
        return record, raw, original

    def snapshot(self) -> dict:
        self.validate_paths()
        record, manifest_raw, original = self.load_manifest()
        data, mode = read_file(self.target)
        span = block_span(data or b"")
        override, _ = read_file(self.project / "AGENTS.override.md")
        pending, _ = read_file(self.pending_path)
        return dict(record=record, manifest_raw=manifest_raw, original=original,
                    data=data, mode=mode, span=span, override=override, pending=pending)

    def inspect(self) -> dict:
        view = self.snapshot()
        warnings = []
        if view["override"] is not None:
            warnings.append(
                "AGENTS.override.md exists. In Codex, a non-empty override takes precedence "
                "over AGENTS.md at this scope; inspect the host's effective instruction chain."
            )
        if view["pending"] is not None:
            status = "interrupted_operation"
            warnings.append("A pending journal exists. Reconcile it before another mutation.")
        elif view["record"] and view["record"]["state"] == "active":
            record = view["record"]
            if record["target"] != self.target_name:
                status = "installed_in_other_target"
                warnings.append(f"Use --target {record['target']} to inspect or remove the installed block.")
            elif view["span"] is None:
                status = "managed_block_missing"
            elif digest(view["data"][slice(*view["span"])]) != record["managed_sha256"]:
                status = "managed_block_modified"
            else:
                status = "installed"
        elif view["span"] is not None:
            status = "unmanaged_block"
        else:
            status = "not_installed"
        return {"action": "inspect", "status": status, "project": str(self.project),
                "target": self.target_name, "target_exists": view["data"] is not None,
                "writes_performed": False, "warnings": warnings}

    def plan(self, action: str) -> dict:
        view = self.snapshot()
        if view["pending"] is not None:
            raise InjectionError("A pending operation journal exists. Inspect and reconcile it before writing.")
        if action == "apply":
            if view["override"] is not None and self.target_name != "AGENTS.override.md":
                raise InjectionError(
                    "AGENTS.override.md exists and can take precedence over AGENTS.md in Codex. "
                    "Inspect effective guidance; explicitly select --target AGENTS.override.md "
                    "only if you intend to update that existing file."
                )
            if self.target_name == "AGENTS.override.md" and view["data"] is None:
                raise InjectionError("This tool never creates a new AGENTS.override.md file.")
        record, data, span = view["record"], view["data"], view["span"]
        active = record is not None and record["state"] == "active"
        if active and record["target"] != self.target_name:
            raise InjectionError(f"An active installation targets {record['target']}; select it explicitly first.")
        if active:
            if data is None or span is None:
                raise InjectionError("The installed target or managed block is missing; refusing to recreate or guess.")
            if digest(data[slice(*span)]) != record["managed_sha256"]:
                raise InjectionError("The managed block was edited. Preserve those edits and resolve the conflict manually.")
        elif span is not None:
            raise InjectionError("A managed-looking block has no active ownership record; refusing to adopt or remove it.")

        if action == "remove":
            if not active:
                return {"noop": True, "status": "not_installed"}
            start, end = span
            separator = decoded(record["separator_base64"])
            # Restore an unchanged, newline-less original exactly. If outside
            # content changed, retain outside bytes instead of guessing intent.
            if separator and data[:start] == view["original"] + separator and not data[end:]:
                start -= len(separator)
            after = data[:start] + data[end:]
            if not record["original_existed"] and after == b"":
                after = None
            updated = dict(record, state="removed")
            return dict(view, after=after, updated=updated, backup=None, status="removed")

        line_ending = newline_for(data or b"")
        managed = self.policy.replace(b"\n", line_ending)
        if active:
            if data[slice(*span)] == managed:
                return {"noop": True, "status": "unchanged"}
            after = data[:span[0]] + managed + data[span[1]:]
            updated = dict(record, managed_base64=encoded(managed), managed_sha256=digest(managed))
            return dict(view, after=after, updated=updated, backup=None, status="updated")

        original = data or b""
        separator = b"" if not original or original == BOM or original.endswith(b"\n") else line_ending
        backup_name = f"{digest(original)}-{uuid.uuid4().hex[:12]}.bin"
        updated = {
            "schema_version": 1, "component": COMPONENT, "project": str(self.project),
            "target": self.target_name, "state": "active", "original_existed": data is not None,
            "original_sha256": digest(original), "backup_file": backup_name,
            "managed_base64": encoded(managed), "managed_sha256": digest(managed),
            "separator_base64": encoded(separator),
        }
        return dict(view, after=original + separator + managed, updated=updated,
                    backup=(backup_name, original), status="applied")

    @contextlib.contextmanager
    def mutation_lock(self):
        self.validate_paths()
        self.metadata.mkdir(mode=0o700, exist_ok=True)
        check_directory(self.metadata)
        flags = os.O_WRONLY | os.O_CREAT | os.O_EXCL | getattr(os, "O_NOFOLLOW", 0)
        try:
            descriptor = os.open(self.lock_path, flags, 0o600)
        except FileExistsError as exc:
            raise InjectionError("Another injection operation may be active; inspect the existing lock before retrying.") from exc
        lock_bytes = f"pid={os.getpid()}\n".encode("ascii")
        try:
            with os.fdopen(descriptor, "wb") as stream:
                stream.write(lock_bytes)
                stream.flush()
                os.fsync(stream.fileno())
            yield
        finally:
            current, _ = read_file(self.lock_path)
            if current == lock_bytes:
                self.lock_path.unlink()

    def execute(self, action: str = "inspect") -> dict:
        if action == "inspect":
            return self.inspect()
        if action not in ("apply", "remove"):
            raise InjectionError("Action must be inspect, apply, or remove.")
        first = self.plan(action)
        if first.get("noop"):
            return {"action": action, "status": first["status"], "target": self.target_name,
                    "project": str(self.project), "writes_performed": False}
        if first["after"] is not None and len(first["after"]) > MAX_BYTES:
            raise InjectionError("The resulting instruction file would exceed the reference-tool size limit.")
        with self.mutation_lock():
            change = self.plan(action)
            if change.get("noop"):
                return {"action": action, "status": change["status"], "target": self.target_name,
                        "project": str(self.project), "writes_performed": False}
            if change["after"] is not None and len(change["after"]) > MAX_BYTES:
                raise InjectionError("The resulting instruction file would exceed the reference-tool size limit.")
            self.backups.mkdir(mode=0o700, exist_ok=True)
            check_directory(self.backups)
            if change["backup"]:
                name, original = change["backup"]
                atomic_write(self.backups / name, original, None)
            journal = json_bytes({
                "schema_version": 1, "component": COMPONENT, "operation": action,
                "target": self.target_name,
                "before_sha256": None if change["data"] is None else digest(change["data"]),
                "after_sha256": None if change["after"] is None else digest(change["after"]),
                "next_manifest": change["updated"],
            })
            atomic_write(self.pending_path, journal, None)
            if change["after"] is None:
                guarded_delete(self.target, change["data"])
            else:
                mode = change["mode"] if change["mode"] is not None else 0o644
                atomic_write(self.target, change["after"], change["data"], mode)
            atomic_write(self.manifest_path, json_bytes(change["updated"]), change["manifest_raw"])
            guarded_delete(self.pending_path, journal)
        return {"action": action, "status": change["status"], "project": str(self.project),
                "target": self.target_name, "writes_performed": True,
                "metadata": str(self.metadata), "backups_retained": True}


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("action", nargs="?", choices=("inspect", "apply", "remove"), default="inspect")
    parser.add_argument("--project", required=True, help="Explicit absolute path to an existing project directory")
    parser.add_argument("--target", choices=TARGETS, help="Canonical target; an override must already exist")
    arguments = parser.parse_args(argv)
    try:
        result = Injector(arguments.project, arguments.target).execute(arguments.action)
    except (InjectionError, OSError) as exc:
        print(json.dumps({"status": "not_completed", "error": str(exc),
                          "inspect_before_retry": True}, ensure_ascii=True), file=sys.stderr)
        return 2
    print(json.dumps(result, indent=2, ensure_ascii=True))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

"""Bounded static checks for the design package, not a JSON Schema validator.

This checks JSON syntax, selected cross-file invariants, local schema references,
and the English-only instruction sources. It never starts either agent host.
"""
from pathlib import Path
import json
import re
import sys

BASE = Path(__file__).resolve().parent.parent


def reject_constant(value):
    raise ValueError(f"Nonstandard JSON constant: {value}")


def unique_object(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"Duplicate JSON key: {key}")
        result[key] = value
    return result


def parse(path):
    return json.loads(path.read_text(encoding="utf-8"),
                      object_pairs_hook=unique_object, parse_constant=reject_constant)


def walk(value):
    if isinstance(value, dict):
        yield value
        for child in value.values():
            yield from walk(child)
    elif isinstance(value, list):
        for child in value:
            yield from walk(child)


def require(condition, message):
    if not condition:
        raise ValueError(message)


def check():
    checks = []
    paths = sorted(p for p in BASE.rglob("*") if p.is_file()
                   and (p.name.endswith(".json") or p.name.endswith(".json.example")))
    objects = {str(p.relative_to(BASE)): parse(p) for p in paths}
    checks.append({"check": "strict_json_parse", "files": len(paths), "status": "passed"})

    english = sorted(p for p in (BASE / "spec").rglob("*") if p.is_file())
    for p in english:
        require(not re.search(r"[\u3400-\u9fff]", p.read_text(encoding="utf-8")),
                f"Unexpected CJK text in instruction/template source: {p.name}")
    checks.append({"check": "instruction_source_cjk_scan", "files": len(english),
                   "status": "passed", "note": "Language was also reviewed; this scan alone cannot prove English semantics."})

    policy = (BASE / "spec/AGENTS.block.en.md").read_text(encoding="utf-8")
    require(policy.count("parallel-development:managed-policy:begin") == 1

            "Managed policy must have exactly one marker pair.")
    skill = (BASE / "spec/parallel-development.SKILL.md").read_text(encoding="utf-8")
    require(skill.startswith("---\nname: parallel-development\ndescription: ")
            and "\n---\n" in skill, "Skill metadata is incomplete.")
    require("Do not downgrade the selected profile" in skill,
            "The Skill must forbid unauthorized profile downgrade.")
    checks.append({"check": "policy_markers_and_skill_metadata", "status": "passed"})

                require(handler["type"] == "command" and handler["async"] is False,

    modern = objects["spec/codex/plugin.json.example"]
    compat = objects["spec/codex/plugin.compat.json.example"]
    require(modern["name"] == compat["name"] and modern["version"] == compat["version"],
            "Codex manifest identities differ.")
    require(modern["extensions"]["com.openai"]["hooks"] == compat["hooks"],
            "Codex hook paths differ.")
    checks.append({"check": "codex_template_consistency", "status": "passed"})

                require(posix["args"] == win["args"] == ["hook", "--adapter", "zcode"],
                        "Unexpected ZCode handler arguments.")
                require(win["command"] == posix["command"] + ".exe", "Unexpected platform paths.")
                require(posix["timeoutMs"] == win["timeoutMs"] == 10000, "Unexpected timeoutMs.")
                require("commandWindows" not in posix and "timeout" not in posix,

                require(posix.get("onError") == ("deny" if event == "PreToolUse" else None),

    checks.append({"check": "zcode_template_consistency", "status": "passed"})

                "Unexpected JSON Schema draft.")
        for node in walk(schema):
            if "$ref" in node:

                target = schema

                patterns += 1

    return {"status": "passed_with_declared_scope", "checks": checks,

                              "Hook execution or enforcement", "Scheduler concurrency tests",
                              "OS sandbox or cross-platform acceptance"]}
